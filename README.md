# RYZOR — локальна збірка

Це статичний сайт для GitHub Pages. Для акаунтів, звернень і чернеток замовлень не потрібні API, Cloudflare, база даних, Google OAuth, Telegram-бот або постійний сервер.

## Що працює локально

- Реєстрація та вхід за email і паролем. Пароль не зберігається відкритим текстом: у браузері обчислюється PBKDF2-хеш із випадковою сіллю.
- Профіль, локальна історія заявок, експорт і видалення даних.
- Створення звернень, локальний список звернень, нотатки й видалення. Надсилання форми не виконує мережевих запитів.
- Вибір тарифу, серійний номер і таймер на 10 хвилин зберігаються локально.
- Платіжний файл не завантажується сайтом. Сайт копіює текст заявки в буфер обміну й відкриває Telegram-чат; користувач сам вставляє текст, прикріплює квитанцію та натискає «Надіслати».
- Каталог ігор, фільтри, модальне вікно, мобільна навігація та статусна панель.

## Важливі обмеження локального режиму

1. Дані акаунта, звернень і замовлень прив'язані до поточного браузера та пристрою. Вони не синхронізуються з іншими пристроями. Очищення даних сайту може видалити їх.
2. Менеджер не отримує звернення, акаунти або замовлення автоматично. Це навмисна поведінка локального режиму. Для відповіді менеджера користувач повинен самостійно написати йому в Telegram.
3. `t.me/st0fen?text=...` відкриває чат із чернеткою. Telegram не дозволяє прикріпити локальний файл через звичайне посилання; квитанцію потрібно додати в чаті вручну. Повідомлення не відправляється, доки користувач сам не натисне кнопку надсилання.
4. Реєстрація не є централізованою автентифікацією. Локальний запис можна змінити через інструменти браузера; це не підходить для захисту платних сервісів або цінних даних. Немає відновлення пароля.
5. Значення ping у серверній панелі — візуальна симуляція у заданих діапазонах, не справжній вимір. Хмарний запуск ще потребує реальних GPU-серверів та відеостримінгу.
6. Повний номер банківської картки навмисно не вбудований у публічні файли. Перед реальним прийманням платежів налаштуйте безпечне платіжне посилання/еквайринг, яким керує дорослий власник рахунку. Не публікуйте карткові реквізити у відкритому репозиторії.

## Публікація на GitHub Pages

1. Розпакуй архів і завантаж вміст папки `ryzor-local` у корінь репозиторію GitHub. Збережи структуру `assets/` та `.github/workflows/pages.yml`.
2. Переконайся, що основна гілка називається `main` (або зміни назву гілки в `pages.yml`).
3. У репозиторії відкрий **Settings → Pages → Build and deployment** та вибери **GitHub Actions**.
4. Зроби commit і push у `main`. Переглянь вкладку **Actions** — workflow має завершитися успішно.
5. Після публікації відкрий адресу GitHub Pages через HTTPS. Web Crypto для обробки паролів потребує secure context; GitHub Pages надає HTTPS.

Ніякі GitHub Secrets для цього локального режиму не потрібні. Не додавай Telegram bot token, Google Client ID, пароль або інші приватні значення у файли сайту.

## Що користувач бачить під час оплати

- Вибирає тариф та натискає «До оплати».
- Сайт створює серійний номер і запускає таймер 10:00.
- Для платного тарифу користувач вибирає файл квитанції (файл залишається на його пристрої).
- Кнопка копіює текст у буфер обміну та відкриває чат `@st0fen`. Користувач вставляє текст, вручну прикріплює файл і надсилає повідомлення.
- Сайт показує подяку за підготовлену заявку, але не стверджує, що гроші вже отримані або підписка активована.

## Рекомендація перед комерційним запуском

Оскільки проєкт орієнтований і на неповнолітніх користувачів, питання платежів, власника платіжного рахунку, повернення коштів, публічної інформації про оператора та обробки персональних даних має перевірити дорослий відповідальний власник. Для справжньої активації підписок потрібне централізоване серверне рішення; чисто локальний сайт не може достовірно підтвердити оплату менеджеру й автоматично оновити акаунт користувача.
