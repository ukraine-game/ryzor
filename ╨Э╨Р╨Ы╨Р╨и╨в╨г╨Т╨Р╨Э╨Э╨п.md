# RYZOR v6 — акаунти, Google, Telegram та підтримка

## Що є у проєкті

- `index.html`, `style.css`, `script.js` — темний сайт без UI-фреймворків.
- `auth.html`, `auth.css`, `auth.js` — окрема сторінка акаунта: Google-перевірка перед реєстрацією, повне ім’я, пароль і повтор пароля; вхід за email та паролем.
- `payment.html`, `payment.css`, `payment.js` — окрема сторінка оформлення підписки, 10-хвилинний таймер, реквізити та завантаження підтвердження.
- `config.js` — лише публічні налаштування сайту. Тут немає і не повинно бути токена бота.
- `cloudflare-worker/worker.js` — serverless API для акаунтів, перевірки Google ID token, оплати, Telegram webhook, перевірки `/start` і двосторонньої підтримки.
- `cloudflare-worker/schema.sql` — таблиці D1 для заявок, повідомлень, запусків і лімітів.
- `cloudflare-worker/wrangler.toml` — приклад конфігурації Worker.

**Важливо:** GitHub Pages — статичний хостинг. Сам HTML/CSS/JS не може приховати токен бота, приймати webhook Telegram або надійно зберігати приватні діалоги. Тому frontend залишається на GitHub Pages, а серверні функції виконує Cloudflare Worker + D1. Це serverless: не потрібно орендувати VPS або тримати процес Python/Node увімкненим. Cloudflare Worker усе одно є серверною функцією, а не «чистим HTML».

## 1. Опублікуй сайт на GitHub Pages

1. Розпакуй ZIP.
2. Завантаж **вміст папки `cloudgaming-site`** у репозиторій GitHub (не сам зовнішній ZIP).
3. У Settings → Pages обери публікацію з потрібної гілки та кореня репозиторію або папки `/docs`.
4. Дочекайся URL сайту. Наприклад: `https://username.github.io/` або `https://username.github.io/repository/`.

Для CORS потрібен саме origin: `https://username.github.io` — без шляху `/repository/` і без кінцевого `/`.

## 2. Створи D1

У Cloudflare Dashboard:

1. Відкрий Workers & Pages → D1 SQL Database → Create database.
2. Назви базу `ryzor-db`.
3. Відкрий створену базу → вкладка Console.
4. Скопіюй і виконай увесь SQL із `cloudflare-worker/schema.sql`.

D1 зберігає акаунти, хеші паролів, хеші сесій, звернення, історію повідомлень, одноразові коди Telegram та ліміти запитів. Пароль не зберігається відкритим текстом і не надсилається до Worker: браузер обчислює PBKDF2-HMAC-SHA256 із випадковою сіллю та 600 000 ітераціями; Worker зберігає лише SHA-256 від отриманого похідного proof. Це також не витрачає CPU-ліміт Worker Free на дорогу KDF. Сесійний токен зберігається в sessionStorage браузера, а в D1 — лише його SHA-256 хеш. Для вже створеної бази повторно виконай повний `schema.sql`: всі нові таблиці створюються через `IF NOT EXISTS`.

## 3. Розгорни Cloudflare Worker

У Workers & Pages натисни Create → Worker → Deploy. Відкрий Edit code та заміни приклад коду в редакторі вмістом `cloudflare-worker/worker.js`. Збережи та натисни Deploy.

У Settings → Bindings → Add → D1 Database додай створену базу з назвою binding:

`DB`

Worker очікує саме `env.DB`.

## 4. Додай налаштування та секрети Worker

У Settings → Variables and Secrets додай:

| Назва | Тип | Значення |
|---|---|---|
| `ALLOWED_ORIGINS` | Text | `https://username.github.io` та, за потреби, origin власного домену через кому |
| `MY_API_KEY_TG` | Secret | Токен `@ryzor_bot`; значення з GitHub Secret потрібно вручну додати і сюди |
| `ADMIN_TG` | Secret | Твій числовий Telegram user ID, лише цифри; додай вручну в Worker Secrets |
| `GOOGLE_CLIENT_ID` або `google_client_id` | Text / Secret | Google OAuth Web Client ID (Worker перевіряє `aud` у Google ID token) |
| `AUTH_SALT_PEPPER` | Secret | Довільний довгий випадковий рядок для захисту від визначення зареєстрованих email |
| `TELEGRAM_WEBHOOK_SECRET` | Secret | Власний довгий випадковий рядок із літер, цифр, `_` та `-` |

**Не вставляй `MY_API_KEY_TG` або `ADMIN_TG` у `config.js`, HTML, JS чи репозиторій.** GitHub Secrets не передаються автоматично до Cloudflare Worker. Створи однойменні секрети також у Cloudflare Worker → Settings → Variables and Secrets (або використай `npx wrangler secret put MY_API_KEY_TG`, `npx wrangler secret put ADMIN_TG` і `npx wrangler secret put AUTH_SALT_PEPPER`). Для `AUTH_SALT_PEPPER` придумай новий довгий випадковий рядок — він не має збігатися з токеном бота чи паролем. `ADMIN_TG` має бути особистим числовим ID саме твого Telegram-акаунта. Worker порівнює його з `from.id` кожної команди. Тільки цей акаунт у приватному чаті з ботом може виконувати `/reply`, `/close`, `/open`. Команди з груп і від інших акаунтів не приймаються. Оплати й звернення також надсилаються тільки на цей ID.

## 5. Відкрий бота та налаштуй webhook

1. Відкрий `https://t.me/ryzor_bot` зі свого Telegram-акаунта адміністратора.
2. Натисни **Start**. Інакше Telegram може не дозволити боту першим надіслати тобі приватне повідомлення.
3. Скопіюй адресу Worker, наприклад `https://ryzor-api.example.workers.dev`.
4. Встанови webhook на адресу `https://ТВІЙ-WORKER/telegram/webhook`, використовуючи той самий секрет `TELEGRAM_WEBHOOK_SECRET`.

PowerShell приклад (підстав свої значення локально; не публікуй команду з токеном):

```powershell
$token = "ТВІЙ_BOT_TOKEN"
$worker = "https://ТВІЙ-WORKER.workers.dev"
$secret = "ТВІЙ_WEBHOOK_SECRET"
Invoke-RestMethod -Method Post -Uri "https://api.telegram.org/bot$token/setWebhook" -Body @{
  url = "$worker/telegram/webhook"
  secret_token = $secret
  allowed_updates = '["message"]'
}
```

Перевір результат методом `getWebhookInfo` через Bot API. Telegram надсилає оновлення на HTTPS webhook і може додавати секретний заголовок `X-Telegram-Bot-Api-Secret-Token`; Worker перевіряє цей заголовок перед обробкою команд.

## 6. Підключи Worker до сайту

Відкрий `config.js` і заповни **лише публічні** параметри:

```js
window.RYZOR_CONFIG = {
  apiBase: "https://ТВІЙ-WORKER.workers.dev",
  googleClientId: "ТВІЙ_WEB_CLIENT_ID.apps.googleusercontent.com",
  payment: {
    bank: "Назва банку",
    recipient: "Ім'я отримувача",
    cardNumber: "0000000000000000",
    iban: ""
  }
};
```

`apiBase` — тільки базова адреса Worker, без `/payment` у кінці. Реквізити тут публічні, бо браузер кожного відвідувача може їх прочитати. Додавай лише реквізити, які власник рахунку офіційно дозволив використовувати для приймання платежів. Для платежів неповнолітніх користувачів потрібна участь дорослого власника рахунку.

Після редагування `config.js` закоміть зміни в GitHub Pages.

## 7. Налаштуй реєстрацію та авторизацію Google

1. У Google Cloud Console створи OAuth Client ID типу **Web application**.
2. У Authorized JavaScript origins додай точний origin GitHub Pages, наприклад `https://username.github.io` (без шляху репозиторію), а також origin власного домену, якщо він є.
3. Скопіюй Client ID у `googleClientId` в `config.js`. Це публічне значення, яке браузер має бачити для відображення кнопки Google. Не плутай його з client secret.
4. У Cloudflare Worker додай `GOOGLE_CLIENT_ID` (або `google_client_id`) з тим самим значенням. Worker звіряє Google JWT-підпис за актуальним Google JWKS, `iss`, `aud`, `exp` та `email_verified` на сервері.
5. Повторно виконай `schema.sql`, якщо D1 створювалася раніше, і розгорни оновлений `worker.js`.

**Реєстрація:** користувач обирає вкладку «Реєстрація» → підтверджує Google → вводить повне ім’я → задає пароль від 10 до 128 символів → повторює пароль. Сервер повторно перевіряє Google ID token і створює акаунт.

**Вхід:** email + пароль. Увійти можуть лише акаунти, які раніше пройшли Google-перевірку. Після успішного входу Worker видає випадкову сесію на 14 днів; браузер тримає її в `sessionStorage`, а не в довготривалому `localStorage`. Введений пароль не надсилається до Worker або Telegram. У браузері з нього обчислюється PBKDF2-HMAC-SHA256 proof (600 000 ітерацій, випадкова сіль), а D1 зберігає лише хеш цього proof. Endpoint отримання солі повертає для невідомих email стабільну секретно-похідну сіль, щоб не видавати наявність акаунта простим повторним запитом.

GitHub Actions workflow з `.github/workflows/deploy-pages.yml` автоматично зчитує Secret `google_client_id` та підставляє значення в `config.js` під час публікації. У браузері Google Client ID буде видимим — це очікувано й безпечно для Web OAuth Client ID. Якщо публікуєш сайт не через цей workflow, впиши Client ID вручну в `config.js`. Telegram token і admin ID ніколи не вставляються в публічну збірку та залишаються тільки в Cloudflare Worker Secrets.

## 8. Як працює перевірка запуску гри

1. Натискання на картку відкриває внутрішнє вікно Ryzor — переходу на Steam немає.
2. Кнопка «Перейти до Telegram» створює одноразовий код запуску в D1.
3. Браузер відкриває `https://t.me/ryzor_bot?start=...`.
4. Після натискання Start Telegram передає `/start <код>` у Worker webhook. Код одноразовий: після першого підтвердження повторне використання не змінює Telegram-акаунт у сесії.
5. Worker звіряє хеш коду, термін дії та позначає перевірку як успішну.
6. Сторінка опитує Worker і показує підтвердження Telegram.

Одноразовий код дійсний 5 хвилин. Старт бота підтверджує лише Telegram-контакт. **Реального запуску гри поки немає**, доки не буде створено сервери стримінгу й систему видачі сесій. Сайт чесно показує цей статус, а не імітує робочий cloud gaming.

## 9. Як користуватися двосторонньою підтримкою

**Користувач:** заповнює форму → отримує `RZ-...` → пише у віджеті «Твої звернення» → сайт зберігає локальний секрет доступу в `localStorage` і регулярно оновлює діалог.

**Адміністратор:** отримує повідомлення в Telegram і відповідає:

```text
/reply RZ-ABC234 Текст відповіді користувачу
```

Відповідь записується в D1, а сайт показує її в тому самому зверненні. Користувач також може відповісти з сайту — нове повідомлення прийде адміністратору в Telegram.

Додаткові команди:

```text
/close RZ-ABC234
/open RZ-ABC234
```

Заявку може переглядати лише той, хто має ідентифікатор **та секретний ключ доступу**. Ключ автоматично зберігається в `localStorage` цього браузера. Якщо очистити дані браузера або перейти на інший пристрій, доступ не перенесеться автоматично — не очищай сховище, поки потрібна історія діалогу. Наступним етапом можна додати експорт/імпорт ключа доступу.

## 10. Оплата та обмеження

- Платні тарифи не приймають підтвердження, якщо власник не додав реквізити та Worker не підключено.
- Підтвердження оплати надсилається тільки в приватний чат `ADMIN_TELEGRAM_ID`.
- Файли обмежено 20 МБ; дозволяються поширені зображення, відео та документи.
- Worker перевіряє назву тарифу й суму на сервері, а не довіряє ціні з браузера.
- Повідомлення про успіх показується лише після позитивної відповіді Telegram Bot API.
- Це ручне підтвердження переказу, а не інтеграція банківського еквайрингу. Автоматично перевіряти надходження на картку ця версія не може.
- Не збирай у формі PIN, CVV, одноразові банківські коди або паролі.

## 11. Перевірка після розгортання

1. Відкрий `https://ТВІЙ-WORKER.workers.dev/health` з браузера сайту. Має повернути `{"ok":true,"service":"ryzor-api"}`.
2. Відкрий `auth.html`, зареєструй тестовий акаунт через Google, перевір вхід і вихід. Переконайся, що email із токена та Client ID збігаються з налаштованим OAuth Web Client.
3. Перевір Telegram `/start` у приватному чаті адміністратора.
4. Створи тестове звернення на сайті й переконайся, що бот отримав його.
5. Відповідай командою `/reply RZ-... Тестова відповідь` і зачекай до 15 секунд або натисни «Оновити» на сайті.
6. Не тестуй платіж справжнім переказом без дозволу власника рахунку. Спершу можна перевірити лише безкоштовну заявку.
