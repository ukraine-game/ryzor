# = Ryzor — налаштування ручного приймання оплат

## Важливо перед публікацією

Сайт поки не має особистих кабінетів, автоматичного білінгу чи реального запуску хмарних сесій. Сторінка оплати створена для **ручного тестового процесу**: користувач заповнює форму, бачить реквізити, додає підтвердження, а адміністратор отримує заявку в Telegram. Не приймай оплату, доки сервіс, правила повернення коштів і реквізити не готові.

## 1. Додай платіжні реквізити

У `payment.js` заповни `PAYMENT_CONFIG`:

- `bank` — назва банку;
- `recipient` — офіційне ім’я отримувача;
- `cardNumber` — номер картки для переказу;
- `iban` — IBAN (необов’язково);
- `workerUrl` — URL Worker, крок 3 нижче.

Ці реквізити будуть публічними на сайті. Додавай тільки ті реквізити, які призначені для приймання платежів від клієнтів. **Не додавай номер CVV, PIN, пароль або токен Telegram.**

## 2. Створи Telegram-бота та чат адміністратора

1. Створи бота через офіційний BotFather у Telegram і отримай токен.
2. Додай бота в приватну групу адміністраторів або відкрий із ним приватний чат.
3. Напиши боту `/start` (у групі — додай бота та надай йому право надсилати повідомлення).
4. Дізнайся ID потрібного чату та збережи його для секрету `TELEGRAM_CHAT_ID`.
5. Не вставляй токен у HTML, JS, GitHub або скриншоти. Якщо токен випадково опублікували — відклич його в BotFather і створи новий.

## 3. Розгорни Cloudflare Worker

Це не окремий сервер Python/Node. Worker — serverless-функція, яка приймає форму та відправляє файл у Telegram.

1. У Cloudflare відкрий Workers & Pages та створи Worker.
2. Встав код із `cloudflare-worker/worker.js`.
3. У Worker → Settings → Variables and Secrets додай:
   - `TELEGRAM_BOT_TOKEN` — як **Secret**;
   - `TELEGRAM_CHAT_ID` — як **Secret**;
   - `ALLOWED_ORIGINS` — домен сайту, наприклад `https://USERNAME.github.io` (без шляху репозиторію). Для власного домену вкажи його окремо через кому.
4. Опублікуй Worker. Його endpoint має закінчуватися на `/payment`; перевір `/health`.
5. Скопіюй URL Worker у `PAYMENT_CONFIG.workerUrl`, наприклад `https://ryzor-payments.example.workers.dev/payment`.
6. Онови GitHub Pages і перевір тестовою заявкою. У Telegram має прийти текст із замовленням і файл.

Обмеження цієї реалізації — 20 МБ на вкладення. Telegram Bot API підтримує документи до 50 МБ, але тут встановлено меншу межу для початкового запуску. Увімкни обмеження витрат/сповіщення в Cloudflare та регулярно перевіряй заявки.

## 4. Як краще зробити двосторонню підтримку

**Рекомендований варіант: Cloudflare Worker + D1 + Telegram-бот.** GitHub Pages лишається фронтендом. Worker створює звернення, генерує короткий ID і секретний ключ перегляду, D1 зберігає повідомлення та відповіді, бот надсилає адміну повідомлення. Адмін відповідає командою на кшталт `/reply RZ-123456 текст`; відповідь зберігається в D1, а сайт показує її у вкладці «Мої звернення» за ID та секретним ключем. Для відповіді можна зробити кнопку «Оновити» або коротке опитування Worker.

**Простіший старт:** GitHub Discussions — публічні теми та відповіді в коментарях. Це швидко й без власної бази, але користувачу потрібен GitHub-акаунт, а приватні платіжні питання там розміщувати не можна.

**Найпростіший приватний канал:** Telegram-бот відкриває приватний діалог з підтримкою. Це двосторонньо, але відповідь приходить у Telegram, а не всередині сайту.

Для Ryzor найкращий баланс — D1 + Worker + бот: і користувач, і адміністратор бачать історію розмови. Перед запуском додай Turnstile або інший захист від спаму, ліміти звернень, політику приватності й терміни зберігання вкладень.

## 5. Важливі нюанси безпеки й таймера

- Десятихвилинний таймер зараз працює у браузері: перезавантаження сторінки почне відлік заново. Для справжнього строку дії заявки потрібна серверна дата завершення в D1 і перевірка Worker перед прийманням файлу.
- Перевірка `ALLOWED_ORIGINS` обмежує браузерні запити з інших сайтів, але сама по собі не захищає endpoint від прямих бот-запитів. Перед відкриттям для всіх додай Cloudflare Turnstile, rate limiting і ліміти витрат.
- Не проси користувача надсилати повний номер його картки, CVV, PIN, пароль банку або одноразовий код. Для підтвердження достатньо квитанції, де зайві платіжні дані приховані.
- Платіжні реквізити мають бути рахунком дорослого власника/офіційного отримувача, який відповідає за приймання коштів і повернення. Не публікуй особисту картку неповнолітнього.
- Після надсилання Worker передає вкладення в Telegram, але не перевіряє факт надходження грошей у банк. Рішення про активацію підписки залишається за адміністратором.
