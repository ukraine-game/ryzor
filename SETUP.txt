RYZOR — ПІДКЛЮЧЕННЯ ДО ВЖЕ НАЯВНОГО СЕРВЕРА

ЦЕ ВЕРСІЯ ЛИШЕ САЙТУ
У ZIP немає server.js, package.json або нового серверного процесу. Сайт підключається до API, який уже працює на твоєму сервері.

1. Завантаж файли сайту в GitHub-репозиторій і опублікуй через свій GitHub Pages workflow.
2. Якщо API доступний на тому самому домені за /api/telegram/notify, api-config.js змінювати не потрібно.
3. Якщо API має окремий домен, у api-config.js вкажи його HTTPS-адресу:
   window.RYZOR_API_BASE = 'https://api.example.com';
4. Наявний API має приймати POST /api/telegram/notify з JSON {"event":"login","details":{}} та самостійно надсилати Telegram-повідомлення.
5. На сервері токен має читатися серверною частиною з приватного random.txt. Не віддавай цей файл браузеру та не розміщуй у публічній директорії.
6. Для окремого домену API налаштуй CORS, дозволивши точний HTTPS-origin твого сайту.

ВАЖЛИВО ПРО БЕЗПЕКУ
Браузер не може прочитати токен із random.txt і водночас приховати його від відвідувачів. Будь-який файл, який JavaScript завантажив у браузер, можна переглянути через DevTools/Network. Тому RYZOR надсилає запит до твого API, а не отримує BOT_TOKEN.

ПЕРЕВІРКА
- У вкладці Network під час погодженої події має бути запит /api/telegram/notify.
- У відповіді та запиті браузера не повинно бути BOT_TOKEN.
- Відкриття https://твій-домен/random.txt не повинно показувати вміст файлу.
- Не додавай справжній random.txt до GitHub. Файл доданий у .gitignore.

СПОВІЩЕННЯ
Відправка можлива тільки після необов'язкової згоди користувача. Передаються лише погоджені події та потрібні для них деталі. Паролі, email, повне ім'я та назва пристрою не надсилаються.
